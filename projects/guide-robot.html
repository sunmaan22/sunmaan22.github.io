배경 · 문제정의

점자블록과 음향신호기가 보급되었지만, 시각장애인은 여전히 정적/동적 장애물 회피, 신호등 인식, 정확한 목적지 안내에서 어려움을 겪습니다. BADUK(바둑이)은 이 세 가지 문제를 하나의 로봇으로 해결하기 위해 시작한 프로젝트입니다. 프로젝트명은 Brake·Avoid·Drive·Update·Keeppace의 앞글자를 딴 것으로, 장애물 앞에서 멈추고(Brake) 피하고(Avoid), 목줄과 IMU로 안내견처럼 자연스럽게 유도하며(Drive/Keeppace) 경로를 실시간으로 갱신(Update)한다는 개발 철학을 담았습니다.

저는 하드웨어 플랫폼 설계·제작, 멀티센서(LiDAR·IMU·터치센서) 통합, STM32 기반 저수준 실시간 제어 및 rosserial 포팅, ROS 센서 드라이버를 담당했습니다.

아키텍처 — Raspberry Pi ↔ STM32

고수준 인지·판단은 Raspberry Pi(ROS1)가, 저수준 모터 제어와 안전 신호는 STM32가 전담하는 이기종 역할 분리 구조입니다. STM32는 ROS를 공식 지원하지 않지만, STM32H7 계열에 rosserial을 직접 포팅해 하나의 ROS 노드처럼 양방향 통신하도록 구현했습니다.

STM32 쪽에는 USART1을 DMA로 수신하고 IDLE 라인 인터럽트로 패킷 경계를 감지하는 STM32Hardware 클래스를 직접 구현해 rosserial의 Hardware 계층을 대체했습니다. 이를 통해 CPU 폴링 없이도 낮은 지연으로 안정적인 ROS↔MCU 통신을 확보했습니다.

핵심 구현

안전 정지 — 터치 센서 게이팅

사용자가 손잡이를 놓치거나 실수로 떨어뜨렸을 때 로봇이 혼자 움직이지 않도록, 터치 센서가 눌려있을 때만 주행 로직이 활성화됩니다. GPIO 상태를 읽어 꺼져 있으면 어떤 조건에서도 즉시 Motor_Stop()을 호출하도록 최우선 순위로 설계했습니다.

목줄 기반 속도 제어 — IMU 상보필터

MPU6050의 가속도·자이로 값을 상보필터(자이로 98%, 가속도 2%)로 융합해 pitch 각도를 계산합니다. 목줄이 아래를 향할수록(pitch > 35°) 더 빠르게 전진하고, 수평으로 놓거나 위로 당기면 정지하도록 매핑해 안내견을 따라 걷는 듯한 자연스러운 감각을 만들었습니다.

DMA 기반 조이스틱 조향

ADC2를 DMA로 연속 스캔해 CPU 개입 없이 조이스틱 값을 읽고, 데드존 처리 후 TIM1 PWM(서보)으로 조향각을 출력합니다. 폴링 방식 대비 지연이 크게 줄어 10ms 주기로도 안정적인 응답성을 확보했습니다.

LiDAR 기반 장애물 정지

2D LiDAR 포인트를 DBSCAN으로 클러스터링해 가장 가까운 객체까지의 거리를 산출하고, /lidar_distance 토픽으로 STM32에 전달합니다. 0.5m 이내로 접근하면 조이스틱·IMU 입력과 무관하게 주행을 차단합니다.

음성 인터페이스 파이프라인

Porcupine 기반 한국어 커스텀 웨이크워드("하이 바둑")로 로봇을 깨우고, VAD로 발화 구간을 감지해 Google STT로 텍스트를 얻습니다. 카카오 로컬 API로 목적지를 지오코딩하고 OSRM 보행자 라우팅으로 경로를 계산한 뒤, 회전 지점마다 gTTS 음성으로 안내합니다. GPS 정확도(HDOP)에 따라 경로 이탈 임계값과 재탐색 민감도를 동적으로 조정해, 신호가 불안정한 환경에서도 과민 재탐색을 방지했습니다.

결과 및 배운 점

하드웨어를 3개월간 두 차례 전면 재설계하며(다이소 박스+스쿠터 바퀴 기반 초기 프레임 › 리튬이온 배터리 4개+PCA9685 통합 전원 보드) 배선 복잡도와 ROS 통신 불안정 문제를 구조적으로 해결하는 경험을 했습니다. 특히 ROS가 공식 지원하지 않는 MCU에 rosserial을 직접 포팅하며 통신 계층을 밑바닥부터 이해하게 된 것이 가장 큰 수확이었습니다.
